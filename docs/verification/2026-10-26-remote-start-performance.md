# 远端新任务启动性能修正

日期：2026-10-26。范围：新任务启动的 SSH 复用、远端批量发现，以及已收到提示词但状态事件缺失时的提前回执核验。未改变模型或用户业务任务。

## 原因证据

- 用户“测试”任务：本地记录 16:11:44.323 受理，16:12:27.251 登记派发，前置流程已耗时 42.928 秒。`dispatched_at` 保存派发意图时间，并非远端实际收到文本的时间；不把任务后续 updated_at 当作严格的启动终点。
- 原路径逐条 SSH 调用 workspace list / pane get / agent get / pane process-info，实测 840、857、884、867 ms；同一命令远端本机分别为 15、9、8、8 ms。
- 上一增量仅优化候选查询及原生查看切换。新任务的 pane 扫描、启动检查和输入确认仍逐条建立 SSH；提示词只有两个字也要走完整流程。

## 实现与边界

- 启动线程拥有私有控制连接，从引用解析到派发/会话确认共用一个 SSH 子进程。固定机器配置、helper 版本和 session，每帧核验主机、session、请求编号；成功、失败及 unwind 回收。连接寿命是单次启动操作，不跨任务池化。
- 远端 helper 一次执行候选 pane 与 Agent 列表的原有检查算法。本地数据库继续负责占用、创建隔离、预占以及每次写入前的有效性检查；实时身份核验不删减。
- `--control-stream-v1` 与只读查询入口分离；控制传输失败不重连、不回退、不重放。完整业务拒绝仍走已有明确 busy 重试；不确定结果保留核实入口。
- 路由与候选查询统一检查 helper 内容哈希。即使还未打开终端或输入 @/$，升级后首次启动也会先安装匹配的 helper。上传期间不持数据库锁，发布前再次核验主机与配置身份。
- 首轮实测发现另一等待：一例状态序号未推进，10 秒后才用精确会话日志确认。现在在原确认窗口内每 5 轮尝试既有回执检查，有证据即提前进入原事务确认路径；提交前再次读取和核验。保留单次 Enter、未知结果不重发和日志证据缺失时的等待。
- 数据库旁新增 `start-timing.jsonl`，只记录操作/机器 ID、阶段毫秒数和结果，超过 2 MiB 后重新开始。它不含受理前的路由/首次 helper 上传、原生窗口显示或模型完成时间。

## 自动化验证

- `cargo test --manifest-path src-tauri/Cargo.toml --lib`：207 passed / 20 ignored。Ignored 为需显式专用环境的既有测试，不算通过。
- 新回归：同一控制进程多帧与 Unicode、明确拒绝后继续；响应丢失、错误 session/请求编号后丢弃且不重连；线程隔离、机器配置固定与 unwind 清理；提前回执只在 Enter 后查询且不额外写入；回执提示后换进程不能完成事务。
- 既有派发未知恢复、落库回滚、任务删除/并发占用、busy 重试和帧超时/取消回归仍通过。

## 真实环境与分阶段结果

Windows Tauri/WebView2 正式版、Herdr 0.9.5、真实 Windows SSH。业务数据库只读复制到隔离目录；新建专用 `kanban-acceptance-start-*` Workspace，使用既有专用验收目录。7 个测试 shell 在隔离数据库中预占，迫使新任务创建自己的 pane。测试提示词精确为“测试”，不向业务 pane 发送输入。

第一阶段仅连接复用/批量扫描的正式版：两次完整启动分别 11.728 秒、21.992 秒；每次均只观察到一个启动控制 SSH 子进程。阶段日志显示准备 pane 约 2.25 秒、准备 Agent 约 5 秒；第二次多出的约 10 秒位于派发确认，最终 evidence 为同一会话的精确消息回执。因此追加提前回执核验。两次原生终端均连接成功，最终精确回执均成立，文件/技能查询返回 4/30 项，测试 Workspace 和隔离应用已关闭。

第一阶段首次 helper 升级含查询约 10.495 秒，单列于上述日常启动时间之外。立即读取日志时一次尚未出现回执，等待写盘后可验证；不把即时无日志等同于未发送，也不重发验收任务。

原始脚本、JSON 与计时日志位于 `.scratch/start-latency/`；第一阶段结果单独保存为 `phase1-result.json`，最终构建结果在 `final/acceptance-result.json`。
