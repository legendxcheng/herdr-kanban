# 首次提示词等待及安全续发验证

规格：[GitHub #47](https://github.com/legendxcheng/herdr-kanban/issues/47)。验证日期：2026-11-08。Windows、本机与 SSH devpc 的 Herdr 0.9.5；Codex CLI 0.167.0。

## 实现及安全边界

新进程首次正文前有界等待 30 秒；明确未写入可显式向原进程继续首次发送。旧 not_sent/flow.not_idle 兼容；旧 unknown、已写正文及人工确认不得从头重发。续发创建新尝试并保留旧记录，固定执行代次、完整进程身份、会话、冻结正文、配置与图片引用。原通用核验及终端重连仍不发送。

故障现场能证明的是派发前 idle→working 的状态竞争，以及明确 not_sent 被送入回执核验循环；尚不能证明重连导致上游状态波动或整体成功率下降。

## 真实连续启动

隔离数据库和专用 Workspace；每轮按顺序启动 10 个真实 Codex，使用中文短文本、含空行/制表符的约 12 KB 文本、末尾字面技能引用。提示词只请求回复唯一 token，禁止工具及文件修改。每项保留原目标、耗时、完整冻结正文、精确 Codex 会话回执及输入阶段日志。

| 环境/轮次 | 结果 | 说明 |
| --- | --- | --- |
| 本机首轮 | 10 次启动返回成功；7 次精确回执 | 3 个长文本样本尾部带空格，Codex 去除尾部空格，精确匹配失败。保留失败记录；只修正验收输入末尾空格，不放宽产品回执匹配。 |
| 本机第二轮 | 10/10 精确回执 | 一次正文和一次 Enter；无重复用户消息。 |
| SSH 首轮 | 4 项完成记录后停止 | 有长文本尾空格匹配失败、正文前超时和正文后 not_idle；停止已知有问题的输入集，未删除原样本。 |
| SSH 第二轮 | 6/10 精确回执，验收未通过 | #5/#10 正文前 30 秒就绪超时；#7 正文已写但 after_text 检查 not_idle，未发送 Enter；#9 上游 agent:start 等待启动超时，未进入派发。失败不自动重试、不替换进程。 |

SSH 失败样本稍后只读查询显示原 Codex 空白输入框及 idle/done，检测规则 `osc_title_idle`；这只能证明稍后恢复，不能反推超时期间可以安全写入。固定 30 秒边界及正文后未知保护按规格保留。**本修复不能宣称 SSH 自动送达已全部可靠，连续基线仍未通过。**
