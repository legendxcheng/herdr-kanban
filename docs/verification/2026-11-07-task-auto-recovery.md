# 任务自动核验、终端重连与只读查看

日期：2026-11-07。规格：[GitHub #46](https://github.com/legendxcheng/herdr-kanban/issues/46)。

## 已实现行为

- 应用拥有恢复协调器，不依赖当前 Workspace 或弹窗。首次观察到有效 unknown、应用启动和主动重试进入有界核验批次：立即检查，随后分别等待 2、5、10、30、60 秒，最多六次。单次 CLI/SSH 仍受原有超时限制。
- 本机最多两项、远端最多三项并发，过期任务的在途请求也保留容量占用。未知完成关闭、空闲清理和 Workspace 创建不自动处理。
- 仅精确提示词回执、已确认派发记录或精确原会话能补齐结果，不重复正文、Enter、Agent 启动或 pane 创建。不以“已连接”或 Agent idle/working 推断本次提示词已送达。
- 传输失败后，独立的机器健康探测每 60 秒至多查询一次，复用相同并发容量和既有请求超时。只对仍有有效未决任务且未停用的机器探测；恢复连通后触发新一轮，不要求使用者返回该页面。
- 人工核实保留两个明确决定，Evidence 改为可选备注。后端自动记录 source、决定、时间、操作和目标；空备注不再被前后端拦截，旧自由文本证据保留。
- 原终端身份可确认时，可以先只读查看，保留 unknown 与原占用。只读在原生传输按允许列表实施，阻止键盘、剪贴板、终端鼠标和 endpoint 执行/菜单控制；保留握手、尺寸、渲染和必要维护。恢复后重新授权交互。
- 每个输入帧检查本地任务、执行代次、操作、占用与查看授权；独立观察约每秒复核实际目标/会话。只读到交互的旧查看租约失效，由当前选择重新连接。跨进程观察与输入并非原子操作。
- 当前任务查看连接短暂失败后自动重连，每轮至多六次；切换任务、电脑或 Workspace 取消旧查看重试。成功连接结束该轮，后续断线可另起一轮；后台恢复不抢选择或焦点。
- 手动派发进入 unknown 的 Todo 任务也可查看原终端，并可重新自动核验；其持久化业务状态与所在列不因此变为已派发。
- 自动和人工恢复共享任务锁。外部查询后、取得数据库事务后及提交前检查取消；会话、派发、绑定、任务和启动结果同事务提交。应用关闭后不发送迟到成功事件。
- 无业务数据库迁移。新增 `task_recovery_status` 与 `retry_task_recovery` IPC；终端输出通道新增 `mode`，查看模式由后端授权。状态轮询只读本机协调器，不触发 Herdr 查询。

## 原生桌面验收

独立 Tauri/WebView2、真实 WezTerm/Herdr 以及上述原终端/会话，本机与 SSH 分别完成：

1. 通过隔离数据库中的未来时间边界暂时隐藏回执，显示原终端的只读模式，派发仍为 unknown。
2. 只终止该验收应用拥有的 WezTerm 查看进程，观察自动重连并恢复只读；Agent 与原会话保留。
3. 切换到 All Tasks，再选择原任务，仍可只读查看；释放测试时间边界后，无需 Confirm 自动恢复交互。
4. 页面刷新后读取已恢复状态；独立的人工核实演练以空备注确认，真实 IPC 成功，证据明确记为 manual。
5. 应用退出后，在隔离数据库重建 unknown；重新启动应用自动核验并恢复连接，原会话不变且派发记录仍为一条。

结果与日志分别位于两个验收目录下的 `desktop/`，包括 `result.json`。原先采用屏幕区域抓取的 PNG 被其他前台窗口遮挡，不能作为 Kanban 或原生终端的画面证据；功能验收依据真实 WebView2 操作、原生客户端就绪/进程、连接回调、Herdr 身份/回执及 SQLite 读回，不将这些截图计为视觉验收。测试脚本位于 `.scratch/verify-recovery-impl/desktop_acceptance.py`。

最终独立提交快照的 Windows debug 二进制 SHA-256 为 `59aefe7ef82806d9943ffd4893f74d1752020383fa5d40c51130fe03f1af9655`，本机和 SSH 桌面测试副本一致。SSH 最终复测于 23:36 完成，额外覆盖仅终止本应用专用 SSH bridge 进程后的自动重连。回执释放后可能等待下一轮退避与远端连接检查，脚本按 150 秒场景上限等待，不作固定 45 秒内恢复的性能承诺。

验收结束后已核对唯一测试 Workspace 标签、ID 与两项 pane 数，关闭本机 `w2B`、远端 `wQ`（首次启动失败）及 `wR`，保留 SQLite/日志/回执证据。未关闭其他 Workspace、Agent 或 Herdr server；清理记录位于 `.scratch/verify-recovery-impl/cleanup.json`。
