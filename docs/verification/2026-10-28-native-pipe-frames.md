# 原生终端大帧写入修复验收

日期：2026-10-28。规格：[GitHub #42](https://github.com/legendxcheng/herdr-kanban/issues/42)。

## 修复与边界

Windows `PIPE_NOWAIT` 命名管道的缓冲区为 64 KiB，原发送实现每次传入整个剩余协议帧。真实约 78–81 KB 的画面帧使写入持续返回零字节，最终触发现有 5 秒写入截止时间；界面复用“任务定位超时”提示。

现有 `Pipe::send` 现在每次最多写 32 KiB，并按实际写入长度推进。分批的是字节流，不是 Herdr 协议帧；长度头、载荷、顺序、64 KiB 管道缓冲区和协议帧大小上限均未改变。一次发送仍只有一个 5 秒截止时间，继续执行原取消、连接有效性和可重试错误检查。没有数据库、IPC、任务派发、绑定、渲染或远端 Herdr 升级改动。

## 自动回归

新增测试直接调用生产管道发送实现，两端使用真实 Windows 命名管道，无写入替身。

- 红灯：在未修改发送逻辑时，`large_frame_reaches_native_client_unchanged` 失败，得到 `terminal.client_focus_timeout`；接收端持续读取仍未收到完整大帧。
- 绿灯：实施分批写入后，该用例通过，接收字节与原始帧逐字节一致，现有组帧器恢复原 payload。
- 大小覆盖包含四字节帧头的 17、65,535、65,536、65,537、81,920、262,144、1,048,576 字节；覆盖双向发送、连续多帧、二进制与 UTF-8 内容。
- 背压覆盖先延迟读取再以不整齐的小块读取；专门的慢读取测试确认即使不断取得进度，也不会延长整体截止时间。
- 接收端不读取、连接取消、Session 关闭和接收端中途退出均有有界返回验证。Windows 在接收端退出时可能报告 `ERROR_NO_DATA`，仍沿用原行为，在发送截止时间内失败，不扩大本次错误处理范围。
- 代码审查后去掉边界测试在成功读取后的多余休眠，避免 Windows 调度粒度放大测试时长；仅暂不可读时等待。随后重新执行相关测试。

## 真实原生窗口与 SSH

使用独立 SQLite、WebView2 数据目录和本机 Herdr session；另建具有明确 `kanban-acceptance-issue42-` 名称的远端 Workspace。三个专用 Codex pane 分别用于本机和远端双任务验收，不提交模型提示词。运行本次生产 Rust 构建的独立 Tauri 应用，通过 Windows UI Automation 操作真实任务卡和按钮，原生 WezTerm CLI 仅向专用 pane 输入未提交标记并读取实际画面。

已直接观察本机及 SSH 原生窗口成功显示，截图保留于本地验收目录。专用远端环境的原生协议探测得到约 81 KB 初始帧：旧写入方式在 5 秒后仍有 81,285 字节未送达；诊断发送器限制为 32 KiB 后，81,281 字节帧在约 1.359 秒完成定位确认。这是辅助大小/机制证据，产品显示验收使用上述实际 Tauri 构建，未把 Python 诊断发送器当作生产修复。

真实桌面记录包括连续任务切换、最大化/恢复、只终止验收实例的查看 SSH 子进程后点击 Reconnect。重连建立新的查看客户端并保留原有会话输入；没有重发 Prompt。输入归属通过对应远端实际 pane 内容交叉核验，不仅检查 UI 的“Herdr open”。

最后一轮完成本机与远端往返、远端双任务快速切换和最大化后的 SSH 断线重连，并查看实际截图确认远端画面恢复。重连前后，三个专用 pane 的终端标识和 shell/前台进程标识均与创建时一致；独立数据库中的派发记录仍为零。

限制：部分连续切换样本中，原生窗口/WezTerm 文本缓冲区曾残留上一任务的字样，实际目标 pane 内容与输入归属仍正确。这个绘制现象未完成根因判断，不作为本次分批写入已解决的事项，也不将切换画面完全无残留标为通过。早期自动化还出现鼠标漏点击及未等待异步输入处理的问题，后续采用可核验的无障碍动作和实际 pane 读取；这些脚本问题未用于修改产品代码。

一次完整输入矩阵还因远端第二个 pane 未观察到 Ctrl+U 清除标记而中止，未继续断言该轮通过。因此，真实大帧显示、断线重连和原进程保留已有证据，完整连续切换的渲染与输入矩阵仍为部分完成。
