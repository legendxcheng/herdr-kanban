# SSH 同步性能修复（2026-11-09）

## 原因和范围

程序发现修复不在列表同步热路径。原路由在每次查询前核验配置、用独立 SSH 执行 hello，业务查询又建立连接。Agent 状态每 3 秒按项目查询，重复连接及重复列表读取随项目数增加。诊断在 devpc 测得三个 hello/workspaces 查询回合分别耗时 2225、2217、2478 ms；六个相同请求复用一条控制连接耗时 1492 ms。这证明重复连接开销，并非对用户反向连接环境的完整复现。

## 实现

- 移除通用路由中的独立 hello。首次实际建连核验 profile，实际业务响应核验主机、session、请求 ID。
- `remote_reads` 只接受明确列举的只读方法，按机器分列表/状态/Git 三类复用连接，避免慢 Git 阻塞列表。配置及 helper 身份变化重建，断线不重发该请求，下一轮读取可以重新连接；停用或退出释放连接。
- 同机项目状态在前端同一微任务中合并为一次 IPC；后端批量读取共享 Workspace 和 Agent 列表，逐 pane 身份检查保留。每项目单独报告错误、发布前核对任务归属；本机查询和其他机器独立。
- 写入与任务操作专用连接不进入此复用池，无数据库迁移，不修改 SSH 配置或用户环境。
