# 点击 Kanban 后原生终端被遮挡：前台切换修复（2026-10-27）

## 复现与根因

用户在安装上一轮版本后反馈：点击 Kanban 界面，WezTerm 立即落到后面。当前安装程序确实包含上一轮 `WindowSync` 修改。现场主窗口 HWND 16918676、查看窗口 HWND 8263864：终端获得前台时，终端在主窗口上方且区域命中终端；主窗口通过系统激活真正获得前台后，顺序变为主窗口在上，终端区域命中主窗口。

对同一现场窗口分别执行异步和同步 `SetWindowPos(terminal, HWND_TOP, ... SWP_NOACTIVATE)`，均返回成功，但 400ms 后终端仍在主窗口下方。只重复或延长重试不能解决这个状态。对照操作先把终端放到主窗口紧下方，再把主窗口放到终端下方，可以恢复终端显示，且前台 HWND 仍是 Kanban；1 秒后保持稳定。

原生回归现在先核验 WezTerm 获得系统前台，再核验宿主获得系统前台，随后运行真实产品 `WindowSync`。上一轮实现明确失败：`activating Kanban leaves the real WezTerm behind it`；本轮修正后通过。测试准备阶段的输入队列临时关联会在产品同步开始前解除，产品没有加入 AttachThreadInput 或 SetForegroundWindow。

上一轮的后台 SetWindowPos 遮挡注入和 WebView 页面点击没有证明 Windows 的 foreground 已切到 Kanban，因此不足以覆盖此次故障。隐藏辅助窗口处理是独立的排序修正，不是本次前台遮挡的完整修复。

## 修正

仅修改原生层级同步与相应回归：

1. 当主窗口持有前台且需要调整时，先观察终端是否紧随主窗口之后，判断时忽略两者的隐藏/附属辅助窗口。
2. 若中间还有其他可见窗口，先把终端放到主窗口紧下方；异步请求后等后续同步读到实际相邻状态。
3. 只有确认相邻后才将主窗口放到终端下方。避免直接把整个 Kanban 降到中间其他应用后面，同时不改变键盘焦点。
4. 终端持有前台、后台跟随、弹窗显隐和原有普通 Z 序约束保持。仍不使用全局 TOPMOST、owner/SetParent 或强制激活。两阶段请求沿用已有有界频率和后验检查。

无数据库、IPC、任务生命周期或终端输入协议变化。
